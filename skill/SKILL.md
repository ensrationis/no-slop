# no-slop: русский слой поверх pstack

Источник правды — плагин **pstack** (`pstack@cursor-plugins`), английский оригинал. Этот файл держит только то, что должно действовать всегда, и то, что относится к нам: язык, наша среда. Если правило здесь расходится с pstack, верен pstack, а этот файл надо поправить.

## 0. Как вызывать pstack

- Один раз за сессию прочитать адаптер `~/.claude/plugins/cache/cursor-plugins/pstack/*/docs/harness/claude-code.md`: он переводит имена Cursor (`Task`, `readonly`, модели, пути) на Claude Code.
- Пользователь вызывает скилл командой `/pstack:<name>`. Агент сам читает `~/.claude/plugins/cache/cursor-plugins/pstack/*/skills/<name>/SKILL.md` и следует ему: инструмент `Skill` большинство скиллов pstack не принимает.
- Шаги, которым нужно то, что есть только в Cursor (Bugbot, Automations, облачные агенты), пропускать одной строкой `Skipped in Claude Code: …` и идти дальше.
- Обновление: `claude plugin update pstack@cursor-plugins`.

## 1. Язык

- С пользователем — по-русски. Код, комментарии, коммиты, PR, issue — на английском, если проект не ведётся по-русски.
- Скиллы pstack не переводить и не пересказывать в чат: применять и называть по имени.
- Русские тексты (ответы, посты, сообщения в чаты, дневник) проходят `unslop` из pstack и поправки `references/prose.md`.

## 2. Неотменяемые правила

1. **Первое сообщение по задаче:** своими словами цель, проблема и самое маленькое изменение, которое её решит. Подтверждения не ждать. Если факты исключают просимое — показать их и остановиться (`in-your-own-words`).
2. **«Готово» — проверяемый предикат,** а не «улучшить».
3. **Каждое утверждение — с доказательством или меткой** *измерено / выведено / догадка*. Проверку, которую можешь сделать сам, не перекладывать на человека.
4. **Вердикты:** VERIFIED, NOT VERIFIED, INCONCLUSIVE. INCONCLUSIVE и проверка не на той поверхности — это не «готово».
5. **Поправка пользователя — механизм, а не текст:** `correct` (архитектура → типы, lint, CI → тест → документация последней).
6. **Развилку «какой подход» сначала классифицировать.** Решается запуском — прототип и сравнение (`arena`, `principle-exhaust-the-design-space`). Спрашивать только о продукте и предпочтениях.
7. **Обратимое — без вопросов, необратимое — с подтверждением** (`principle-never-block-on-the-human`). Необратимое: force-push в общие ветки, деплой, удаление данных, сообщения наружу.
8. **Называть принцип, только если он изменил конкретное решение,** и какое.
9. **Комментарии** — только для «почему», навязанного внешней системой (`no-comments`).
10. **Сломанный скилл или инструмент** чинится отдельным изменением, без молчаливых обходов.

## 3. Маршрут: задача → скилл pstack

| Задача | Скилл |
|---|---|
| Любая нетривиальная работа с кодом | `poteto-mode` (плейбуки bug-fix, feature, refactoring, investigation и др.) |
| Сначала форма: типы, сигнатуры, модули | `architect` |
| Несколько кандидатов, выбрать и срастить лучшее | `arena` |
| Параллельный обход, гонки, исследование | `swarm` |
| Баг с дешёвой локальной целью теста | `tdd` |
| «Это безопасно?» | `blast-radius` |
| Цифры производительности | `benchmark-checklist` |
| Нужен способ проверять UI, CLI, сервис | `create-verification-skill`, `maintain-verification-skill` |
| Гонки, повторы, машины состояний | `create-formal-verification-skill`, `statechart` (Java и TLC ставит сам через `mise`, первый запуск дольше) |
| Агент повторяет ошибку | `correct` |
| Долгий или ночной автономный прогон | `figure-it-out`, `show-me-your-work` |
| Adversarial-ревью изменения | `interrogate` |
| Как устроено / почему так | `how`, `why`, `teach` |
| Углубить задачу перед стартом | `sharpen` |
| Разбор сессии в правки скиллов | `reflect` |
| TypeScript | `typescript-best-practices` |
| Документация и тексты | `technical-writing`, `unslop` + `references/prose.md` |

## 4. Запреты, которые действуют всегда

- `setTimeout(fn, 0)`, `requestAnimationFrame`, `requestIdleCallback`, `sleep N` и повторы «на всякий случай» как способ подождать. Ждать конкретное событие или состояние.
- Заглушки, скрывающие баг: guard, повтор, проглоченная ошибка, выброшенное состояние.
- `as` без валидации, `any`, `!`.
- Markdown-файлы, о которых не просили; комментарии-оправдания.
- «Готово» или слияние по зелёному CI без живого прогона.
- Ослабление проверки, теста или предиката, чтобы прошло.
- Параллельные агенты в одном рабочем каталоге.

## 5. Наша среда

Если в глобальном `CLAUDE.md` заведён дневник работы (`journal/`, `STATE.md`, `journal-note`), журнал решений из `show-me-your-work` его не заменяет: в дневник — итог и решения, в TSV — ход прогона.
